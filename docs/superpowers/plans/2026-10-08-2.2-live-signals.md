## Why (evidence)

**#1068, PROD 08.10.2026.** Forecast.Solar said 18.3 kWh; the day made 4.3 kWh. `sensor.sem_energy_plan.computed_at` stayed `09:02` all day with `home_grid_w = 0` for 10:00–17:00, while the house imported ~1 kW every hour. Three causes, all read in code:

1. **The plan's day slots read the RAW provider remaining.** `coordinator.py:10545-10550` builds `build_day_slots(day_kwh=forecast_data.forecast_remaining_today_kwh)`. The dampened value is deliberately local (#598, `coordinator.py:5968-5985`) and never reaches the plan.
2. **The live correction cannot go below 0.5.** `ForecastTracker._calculate_dampening_factor` clamps `max(0.5, min(1.5, blended))` (`forecast_tracker.py:~585`). PROD showed `sem_forecast_dampening_factor = 0.5` (clamped low); the true ratio was 0.23. The clamp is right at dawn (tiny `expected_fraction` amplifies noise) and wrong at noon with confidence 1.0.
3. **A replan with the same decision keeps the old trajectory.** The supply term of `_energy_plan_demand_signature` (`coordinator.py:9099-9150`) re-anchors on a ≥ 3 kWh gap and replans; with no demands, `plan_decision_core` (`:173`) compares equal and the #775 branch (`:9946-9958`) restores `_prev_plan_775` — slots included. So the card shows the 09:02 sky all day.

**#1021.** Grid operators (DE §14a EnWG, CH Rundsteuer) signal "reduce load". Solar Manager and CLEMAP keep solar charging alive while it is on. Note: **#664 removed a dead utility-signal surface on Guido's word (26.07)**; `tests/test_664_no_utility_signal_surface.py` says a real implementation must delete that test as part of the feature. #1021 is that implementation — see Decision D1.

## Part B — #1021 the grid operator's "reduce load" signal

**What the signal means (research, 08.10).**

- **Germany, §14a EnWG.** The operator never cuts a device below 4.2 kW. With an energy manager it sets ONE limit at the grid connection — 4.2 kW × a simultaneity factor from the BNetzA table — and the manager shares it out. Own solar on top is allowed: the limit is on GRID DRAW. evcc does exactly this (relay or EEBus → a temporary `maxPower` on a load-management circuit).
- **Switzerland, Rundsteuerung.** The utility's own relay cuts boilers / heat pumps (max 2 h per block, 6 h per day; legacy signals allowed until end of 2027; customers may object). SEM can enforce nothing there. Its job is to KNOW the device is locked: do not plan it, do not count it as available, say "locked by the grid operator".

So SEM supports two shapes, both default OFF:

1. **Cap mode (DE):** while the signal is on, the grid ceiling becomes `min(saved peak limit, signal cap)`. The existing peak machinery does the rest — #864 slot bound and EV sizing, the night/day plan headroom, the load manager's shedding. Solar on top stays allowed because every one of those guards measures grid import.
2. **Lock awareness (CH):** a device can be marked "behind the operator's relay". While the signal is on, that device is LOCKED: SEM does not plan it, does not count it as available, does not try to start it, and shows the reason.

Authority stays **house fuse > signal cap > solar**: the user's emergency level and #747's emergency clamp are untouched; the signal only lowers the target below them. No EEBus code in SEM (integrations, not hardware): if an integration publishes the EEBus LPC value as a sensor, the user may pick it as the cap.

**Inputs (option growth = 2, plus one per-device flag; see D6):**
- `shed_signal_entity` — one `binary_sensor` / `input_boolean` (relay contact through any integration).
- `shed_signal_limit` — kW, default 4.2; the same field accepts a sensor entity instead of a number (EEBus LPC value).
- per device: `behind_operator_relay` (bool, default off) in the load config modal.

- [ ] **Step 2: Implement**

```python
"""(#1021) The grid operator's "reduce load" signal (§14a EnWG, Rundsteuer).

One optional relay entity; ``on`` = active. While active, ``cap_kw`` is the
grid-import ceiling the operator allows (DE). Anything unreadable on the
relay = NOT active, and the state says why: the operator's own relay is the
hard enforcement, SEM's part is to stay under it, not to lock a house out of
its grid on a broken wire. An unreadable CAP falls back to 4.2 kW, the legal
per-device floor — never to "no cap"."""
from dataclasses import dataclass
from typing import Callable, Optional, Union

LEGAL_FLOOR_KW = 4.2

@dataclass(frozen=True)
class ShedSignal:
    active: bool
    source: Optional[str]
    state: str                  # none | on | off | unavailable | unknown
    cap_kw: Optional[float]     # set only while active

def _cap(limit: Union[float, str, None], get_state: Callable) -> float:
    if isinstance(limit, (int, float)) and not isinstance(limit, bool) and limit > 0:
        return float(limit)
    if isinstance(limit, str) and "." in limit:
        st = get_state(limit)
        try:
            v = float(getattr(st, "state", ""))
            if v > 0:
                return v
        except (TypeError, ValueError):
            pass
    return LEGAL_FLOOR_KW

def read_shed_signal(entity_id, limit, get_state) -> ShedSignal:
    if not entity_id:
        return ShedSignal(False, None, "none", None)
    raw = str(getattr(get_state(entity_id), "state", "unknown") or "unknown").lower()
    if raw in ("on", "true"):
        return ShedSignal(True, entity_id, "on", _cap(limit, get_state))
    if raw in ("off", "false"):
        return ShedSignal(False, entity_id, "off", None)
    return ShedSignal(False, entity_id,
                      raw if raw in ("unavailable", "unknown") else "unknown", None)
```
