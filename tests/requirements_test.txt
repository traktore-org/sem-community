# pytest-homeassistant-custom-component pins ONE exact Home Assistant per
# release, and each release has a Python floor. So the interpreter is the HA
# selector, and the CI matrix's `python-version` list is really an HA list
# (#787). Written as markers rather than a single pin so `pip install -r` does
# the right thing on every leg, and so the mapping is visible in one place:
# for nineteen months both matrix legs installed 2025.1.4 and nothing said so.
#
# (#836) The 3.12 -> HA 2025.1.4 rung is GONE, along with the 2025.1 floor it
# verified. Of 62 issues stating an HA version, the oldest ever reported is
# 2026.4.3 and not one is on 2025.x — and since the old floor let those users
# install and file, that is absence, not sampling. The rung was proving a
# version nobody runs.
#
# 2026.2 is also the ceiling for this mechanism: it is the LAST HA that runs on
# Python 3.13. Everything from 2026.4 up needs 3.14, so a higher floor makes
# every rung 3.14 and the interpreter can no longer select the HA — that would
# mean re-cutting the matrix around the phacc version instead. Deliberate
# choice, not an accident of the next bump.
#
# Pinned exactly, per rung. Bump deliberately — and update the `->` note, which
# tests/test_787_ha_version_matrix.py reads.
